# Fixes to the reliability candidate — November 9, 2026

Made on `claude/packet-builder-fixes-20261109`, based on `6d00786` (the reliability commit `4a017d8` plus the ChatGPT adapter). A code review of `4a017d8` found defects that would have stopped real builds and left finished matters unable to reach Ready to file. This change fixes them. Nothing was installed, released or pushed, and no client matter was touched.

## What changed

| Problem in `4a017d8` | Now |
|---|---|
| The tool hook refused every background agent any tool outside eleven local ones, and any shell command with `$`, `\`, a pipe, `&`, `;` or a line break. The skills teach exactly those commands, and `Skill` and `ToolSearch` were not on the list. It applied to every agent in every session. | Local tools (skills, tasks, agents included) and local shell commands always pass. Research is screened for client details as before. In a matter run's own agents, a shell command that reaches the network is screened the same way, and other outbound tools are refused. Agents doing unrelated work are affected only by the research check. (`hooks/privacy.ts`) |
| A finished matter showed Draft packet until an approval button on the Packet tab was pressed; the Overview never mentioned it, and the server called the status "Approved for filing". | Ready to file is the status again. Its card says the packet is marked DRAFT until approved and offers **Approve for filing**. A draft can be approved from More you can do. |
| Approval could not pass on a real build: it read form-audit results in a shape the audit does not write, hashed working folders that clean-up deletes and records the app rewrites, required every packet ever recorded to exist under its first name, and lapsed seven days after the research check. Blockers were shown as raw text. | Approval is the attorney's sign-off and is always possible once a packet is assembled. Everything still open is listed in plain words and approving with any of it open takes a written reason, kept on the record. An approval covers the packet, the letter, the forms and the client's documents, and holds until one of them changes. (`scripts/filing_readiness.py`, `scripts/draft_packets.py`) |
| "security" in the sensitive-answer pattern matched "Social Security", so every SSN answer needed a dated client confirmation. | The pattern excludes "Social Security". None of the 15 SSN questions across the form schemas is flagged; the security-grounds questions still are. |
| One letter the form's font cannot print (Nguyễn, Łukasz) stopped the whole form. | That box is left blank, the rest of the form is filled, and the build suggests an attorney decision the audit ties its finding to. Nothing is transliterated. |
| A cover letter edited in Word, a packet marked up in Preview, or any matter built before this version refused to rebuild. | The edited file is moved to `Your edited copies` beside it and the rebuild goes on; the tool tells the step to raise one open item. A file with no receipt is treated as generated. A renamed packet is found by its contents. |
| Protected matters were listed as "Matter 3F9A21C0B7". | The folder keeps its neutral name. The app shows the name the attorney gave it (`title` in the payload), and requests to Claude still name the folder. |

Smaller items in the same commit: the runtime now accepts the final review's `reject_likely`; the circuit is chosen from named choices instead of typed as `ca5`; the T and U case-type notes are in plain words; a name that is also an everyday word ("May", "Long") no longer blocks every research query that contains the word; the filing check runs only for the open matter and caches file hashes, instead of hashing every finished matter on each 15-second refresh.

## Decisions worth knowing

- **Approval no longer refuses.** Open items needed before filing, unfinished steps, review notes, form-check errors and an old research check are warnings that require a reason, not blocks. Approval is impossible only when no packet is assembled or its clean copy is missing or changed.
- **The case-theory map is no longer part of approval.** It is an internal working record; no step verifies it, so it would have shown a warning on most matters.
- **The shell rule screens network commands rather than allowing a fixed list.** Past builds issued about 230–250 shell commands each, mostly one-off compound commands; a fixed list would refuse most of them. This is a workflow safeguard, not a sandbox, as `senior-associate-claude/docs/DATA-HANDLING.md` says.
