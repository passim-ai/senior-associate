# Fixes to the reliability candidate — November 9 and 10, 2026

Made on `claude/packet-builder-fixes-20261109`, based on `6d00786` (the reliability commit `4a017d8` plus the ChatGPT adapter). A code review of `4a017d8` found defects that would have stopped real builds and left finished matters unable to reach Ready to file. Fixing them took three passes: the first from reading the code, the second from an independent review and a probe in the desktop app's engine, the third from a full build of the sample matter and a further review. This is the record of all three. What was tested before release is in [release-1.3.0.md](release-1.3.0.md).

## Decisions worth knowing

- **Approval no longer refuses.** Open items needed before filing, unfinished steps, review notes, form-check errors and an old research check are warnings that require a reason, not blocks. Approval is impossible only when no assembled packet is in the matter's folder or its clean copy is missing or changed.
- **The case-theory map is no longer part of approval.** It is an internal working record; no step verifies it, so it would have shown a warning on most matters.
- **The gate names what it refuses, not what it allows.** The host adds tools with each release, and one missing from an allow-list stopped every build. A new host tool that sends information elsewhere will pass until it is added to the refused list.
- **A shell command is read broadly, and only written text is left out.** An address, a program that connects, or code that connects, anywhere in a command, makes it one that is screened. Reading a command's reach from the programs it runs was tried and missed too much. Builds issue about 230 to 400 shell commands each, mostly one-off compound commands; in the sample build none reached the network. A script written to a file and then run is not read. This is a workflow safeguard, not a sandbox, as `senior-associate-claude/docs/DATA-HANDLING.md` says.
- **A matter with no recorded name is no longer refused all research.** A folder named by a file number would otherwise fail its first step.
- **The first rebuild of a matter made before 1.3.0 keeps its letter and packet as earlier copies,** with one open item asking whether they had been edited. That is one extra item per matter, once, in exchange for never losing an edit.
- **One packet per part.** Each assembly replaces the same packet under its other name and the upload files split from it. A split filing's two parts are two assemblies.

## Verification

See [release-1.3.0.md](release-1.3.0.md). In short: a full build of the fictional sample matter passed all 10 steps in the desktop app's engine, the approval steps worked on its output, the full suites for both plugins pass, and the workflow ran on GitHub for the first time.

## Not done

- The panel has not been used in the desktop app with this version, and no build has run in the default permission mode.
- The ChatGPT adapter's own hook (`senior-associate-chatgpt/chatgpt/privacy_hook.py`) still has the fixed shell-command list this change removed from the Claude plugin.
- The Python name matching used by the command-line network gate and the privacy lint (`scripts/privacy_terms.py`) still matches everyday-word names in any case.
- The skills still disagree on whether a yes/no eligibility answer may default to "No".
- A precedent cited by a short name that is also a party's surname is still refused; so is a search containing a first name or title read from the documents.
